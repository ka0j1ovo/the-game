# The Game · 黄狗国赛事数据中心

纯前端单页应用：没有后端、没有构建步骤，双击 `index.html` 就能用。

## 目录

```
index.html            页面骨架
css/style.css         样式
js/app.js             全部逻辑（路由 / 渲染 / 赛制 / 存储）
data/esports-data.json  内置数据集（人类可读的唯一数据源）
data/seed-data.js       内置数据集打包版（由脚本生成，index.html 直接加载）
data/README.md          数据契约：改代码前先读
tools/build-seed.mjs    从导出的 JSON 生成内置数据集
```

## 数据存在哪

- **内置静态数据集**：`data/seed-data.js`，随网站发布，清缓存/换浏览器都不会丢；
  启动时会把本地缺少的赛事、阶段、对局补齐，已有内容不覆盖。
- **运行期存储**：IndexedDB 主存 + localStorage 镜像，写入失败会常驻提示；
  每 5 分钟自动快照，清空/导入/覆盖前也会自动快照，可在「存储与备份」里回滚。
- **注意**：`file://` 打开和 `https://…github.io/…` 打开是两套互不相通的浏览器存储，
  换地址前请先用「导出 / 导入」。

## 更新内置数据集

```bash
# 1. 在网站里改好数据 → 右上角「导出」
# 2. 用导出的文件重新生成内置数据
node tools/build-seed.mjs "esports-data (1).json"      # 也可以直接用仓库里的规范化数据：
node tools/build-seed.mjs --from data/esports-data.json
```

脚本会校验数据完整性（重复 id、框图连线指向、分组引用）并生成版本号。
详见 [data/README.md](data/README.md)。

## 批量录入

赛事详情页右上角「批量录入」，或每个阶段标题旁的「批量录入」。

```
双败胜者组第一轮 DRE 3:1 DGE  RBG 3:0 BOTV
败者组第一轮 FLC 2:0 FOR
【总决赛】DRE 3:2 RBG
```

- 每行一场，一行多场用**空格 / 分号 / `|`** 分隔；
- 轮次可以单独一行，或用 `【】` `[]` 标注，或直接写在行首（`胜者组第1轮`、`双败胜者组第一轮`、`小组赛A组第1轮`、`总决赛` 都能识别）；
- 比分支持 `3:1`、`3-1`、`3比1`、全角 `3：1`；还没比分就写 `A vs B`；
- 队伍按**简称或全称**匹配；缺失的队伍可勾选「自动创建未知队伍」；
- 会优先填进**同轮次、双方队伍都对得上的空位**，胜者自动推进到下一轮；
- 淘汰赛默认不新增对局（避免破坏框图结构）；小组赛/瑞士轮默认允许新增。

### 截图识别（可选）

「批量录入」里的「从截图识别」可以调用**你自己的** OpenAI 兼容视觉接口
（接口地址 + 模型 + API Key，Key 只存本机 localStorage，不随导出数据带走）。
图片会发送到你填的接口，识别结果先转成上面的文本让你核对，确认后才写入。

## 修改赛制/渲染时的注意事项

渲染层只读取 `stages[].matches[]`（含 `nextId` / `loserNextId` 连线），
**不要为了换布局而重新生成对局数据**；需要调整结构时，在 `normalizeState()` 里写向前兼容的迁移。
这样无论前端怎么重构，已有的赛制框图数据都还在。
